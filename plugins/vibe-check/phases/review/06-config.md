# Phase 0.6 — Resolve config

> **Lazy-loaded.** Read from the command spine (`commands/review.md` or `commands/deep-review.md`) when Phase 0.6 is entered (every mode, unconditional, after Phase 0.5 and before Phase 0.7).
> Announce on entry, after this Read: `✓ Phase 0.6 — Resolve config`.

**UNCONDITIONAL — runs on EVERY mode (GSD phase / plain diff / PR / range / `--all`) and is delegated to `/deep-review`.** This step reads the repo-root `.vibe-check.toml` **exactly ONCE per run** and carries the resolved values forward to the three consumers (the Phase-2 Selection table, the Phase-3 score.py envelope, and the Phase-4 config-health line). It is placed between Phase 0.5 and Phase 0.7 — both of which are unconditional and both delegated to `/deep-review` — SPECIFICALLY so the config read fires on all modes and both commands, BEFORE any dispatch decision that consumes it. It MUST NOT be moved inside Phase 1.5 (GSD-phase-only — `$PHASE_ID` unset on diff/PR/range/`--all`) or inside any `$ALL_MODE`/`$PHASE_ID`-gated block; doing so would make `.vibe-check.toml` silently inert on the common modes. Announce on entry:

```
✓ Phase 0.6 — Resolve config
```

**Bind this step's OWN repo root FIRST (do NOT reuse `$ROOT`).** `$ROOT` is bound only INSIDE the Phase-0 mode-5 `--all` branch (mode-5 step b in `$VC_ROOT/phases/review/00-scope-all.md`, `ROOT=$(git rev-parse --show-toplevel)`), so it is EMPTY on plain diff / PR / range / GSD modes — reusing it here would make `config.py` silently degrade to no-config on the common paths. Bind a fresh, mode-independent root at the TOP of this block, unconditionally (the same idempotent call Phase 0 uses, but its own variable). If `git rev-parse` yields empty (not a git repo / detached), config.py still degrades safely to no-config — acceptable; the common case binds a real root.

```bash
CONFIG_REPO_ROOT=$(git rev-parse --show-toplevel 2>/dev/null)
```

**Parse the `--min-confidence N` flag HERE (mode-independent — D-04, CONF-02/03).** `--min-confidence` applies to ALL 5 modes (diff / PR / range / GSD / `--all`) and is delegated to `/deep-review`, so it belongs in this unconditional config-resolution step — NOT the `$ALL_MODE`-only mode-5 flag block (mode-5 step a in `$VC_ROOT/phases/review/00-scope-all.md` binds `--full`/`--fix`/`--include-docs`, which "add NOTHING to the four diff handlers"; a universal flag would be silently inert there on the common modes). Extract the flag's token from `$ARGUMENTS` (accept both `--min-confidence 75` and `--min-confidence=75`; capture only the token, do NOT range-check it here) into `$MIN_CONFIDENCE_FLAG_VAL`. The 0–49 bound (Fable A3: ≥ 50 is refused because the pre-scoring filter would silently drop findings that score into the critical band) is NOT re-implemented in this prose: the token is threaded through `config.py` below, so `config.py`'s tested `_validate_min_confidence` owns validation (a bad token like `999` — or a critical-annihilating `60` — degrades to no-filter + one warning that flows through `$CONFIG_WARNINGS`). When the flag is absent, `$MIN_CONFIDENCE_FLAG_VAL` is empty — byte-identical to today's no-flag path.

```bash
MIN_CONFIDENCE_FLAG_VAL=$(printf '%s' "$ARGUMENTS" | sed -n 's/.*--min-confidence[ =]\([^ ]*\).*/\1/p')
```

**Parse the `--codex on|auto|off` flag HERE (mode-independent — D-10, LEGIBLE-02).** `--codex` is a UNIVERSAL flag that applies to ALL 5 modes (diff / PR / range / GSD / `--all`) and is delegated to `/deep-review`, so it belongs in this unconditional config-resolution step — NOT the `$ALL_MODE`-only mode-5 flag block (RESEARCH Pitfall 7: a universal flag would be silently inert there on the common modes). Extract the flag's token from `$ARGUMENTS` (accept both `--codex on` and `--codex=on`; capture only the token, do NOT validate `off`/`auto`/`on` here — `config.py`'s tested `_validate_codex` owns validation, coercing anything invalid to `auto`) into `$CODEX_FLAG_VAL`, mirroring the `--min-confidence` parse verbatim. The Task-1 pre-mode normalizer does NOT remove the token from `$ARGUMENTS` (it strips into the SEPARATE `$SCOPE_ARGS` used by mode detection), so this parse of `$ARGUMENTS` still finds the flag in EVERY mode — including the flag-only default-diff call the mode-1 rewire now routes correctly. When the flag is absent, `$CODEX_FLAG_VAL` is empty — byte-identical to today's no-flag path.

```bash
CODEX_FLAG_VAL=$(printf '%s' "$ARGUMENTS" | sed -n 's/.*--codex[ =]\([^ ]*\).*/\1/p')
```

**`scripts/config.py` shares the Phase-0 TRUST-01 resolver with `$SCORE_PY`, but INVERTS the terminal arm to DEGRADE, never `exit 1`.** The config reader is OPTIONAL where the scorer is MANDATORY (Pitfall 4): a missing `score.py` HALTS the review (fail-closed), but a missing `config.py` means "no config" → all defaults, and the review still runs. `$CONFIG_PY` is resolved ONCE by the Phase-0 TRUST-01 resolver from the trusted plugin root, never from the reviewed repo; if it does not resolve, `$CONFIG_PY` is empty and this phase continues with all-defaults. **Do NOT "fix" this terminal arm back to fail-closed** — the divergence from `$SCORE_PY` is deliberate and load-bearing.

`$CONFIG_PY` was bound ONCE by the Phase-0 TRUST-01 resolver and carried forward — substitute that resolved absolute path in the invocation below and do NOT re-resolve it here. Its terminal arm is this consumer's DEGRADE (the INVERSION vs `$SCORE_PY`'s `exit 1`): when `$CONFIG_PY` is empty there is no config reader, so the run continues with all defaults.

```bash
# (4) DEGRADE — none resolved (the INVERSION vs $SCORE_PY's `exit 1`): no config reader → run with all defaults.
#     CONFIG_PY stays empty; the invocation below is skipped and the resolved vars default (see the parse block).
```

**Invoke the helper ONCE — same compound-Bash shape as the mode-5 `python3` heredoc / the `$SCORE_PY` invocation (`$(REPO_ROOT="…" python3 "$CONFIG_PY")`), data via the `REPO_ROOT` env var, stdout captured to a shell var, no temp file, no `allowed-tools` change.** Pass `$CONFIG_REPO_ROOT` — NEVER `$ROOT`. `config.py`'s `__main__` reads `$REPO_ROOT`, resolves `$REPO_ROOT/.vibe-check.toml`, and emits `{"values": {...}, "warnings": [...]}` on stdout with `exit 0` ALWAYS.

**Thread `--min-confidence` AND `--codex` through config.py for validated precedence (D-04/D-10, option a).** Pass `$MIN_CONFIDENCE_FLAG_VAL` AND `$CODEX_FLAG_VAL` on the SAME invocation via the `MIN_CONFIDENCE_FLAG` and `CODEX_FLAG` env vars (Plan 31-01 / 33-01 `__main__` interface). `config.py`'s `__main__` forwards each parseable flag through the tested `_apply_flags`, so the flag runs the SAME validation bound as a toml value — resolving `flag > config > default` inside config.py with NO precedence prose here and NO duplicated `off`/`auto`/`on` or 0–49 check. An empty `MIN_CONFIDENCE_FLAG` / `CODEX_FLAG` (no flag) means "no override": the resolved value is then the toml value (or the built-in default — `min_confidence` None, `codex` `auto`) — byte-identical to today. A non-int `min_confidence` token / invalid `codex` token is coerced by `__main__`/`_validate_codex` (the shim still exits 0). Because both flags ride the config invocation, `/deep-review` inherits them for free (it runs this unconditional Phase 0.6 by delegation).

```bash
if [ -n "$CONFIG_PY" ]; then
  CONFIG_JSON=$(REPO_ROOT="$CONFIG_REPO_ROOT" MIN_CONFIDENCE_FLAG="$MIN_CONFIDENCE_FLAG_VAL" CODEX_FLAG="$CODEX_FLAG_VAL" python3 "$CONFIG_PY")
  CONFIG_EXIT=$?
else
  CONFIG_JSON=""
  CONFIG_EXIT=0
fi
```

**Flag WITHOUT a resolvable `config.py` (the `$CONFIG_PY`-empty arm).** If no `config.py` resolved (arm 4 above) but `--min-confidence` WAS passed, the flag cannot be validated/applied — `$CONFIG_MIN_CONFIDENCE` stays None (no filter). Likewise for `--codex`: with no reader `$CONFIG_CODEX` cannot be validated, so it degrades to `"auto"` (behavior-unchanged — a broken/absent reader must still run Codex per today's auto logic), NEVER None. This matches the degrade posture: a partial install without the reader behaves as v2.7 (no filtering, Codex on auto), never crashes. The common case (working-tree copy present) always resolves `config.py`, so both flags apply.

**Parse ONCE into carried-forward vars — `$CONFIG_THRESHOLDS` / `$CONFIG_DISABLED` / `$CONFIG_TOP_MODEL` / `$CONFIG_MIN_CONFIDENCE` / `$CONFIG_IDIOM_FLOOR` / `$CONFIG_CODEX` / `$CONFIG_WARNINGS`.** These are the SINGLE resolved config state the rest of the run reads — there is NO second read anywhere (Phase 2 dispatch, Phase 3 envelope, Phase 4 report, and `/deep-review`'s own consumption all read these vars, never re-invoke `config.py`). From the parsed JSON: `$CONFIG_THRESHOLDS` ← `values.thresholds` (a `{critical,warning,medium}` dict, or None/absent); `$CONFIG_DISABLED` ← `values.disabled` (a list, possibly empty); `$CONFIG_TOP_MODEL` ← `values.top_model` (`opus`/`fable`/None); `$CONFIG_MIN_CONFIDENCE` ← `values.min_confidence` (an int in 0–49 after config.py's `flag > config > default` precedence + validation — ≥ 50 is refused upstream with a critical-drop warning, Fable A3 — or None when no flag and no valid config value; None means no filtering); `$CONFIG_IDIOM_FLOOR` ← `values.idiom_floor` (a band name INCLUDING `"low"`, the `"medium"` default when config is present-but-unset, or the literal `"off"` sentinel when the user explicitly disabled the cap — config.py Plan 32-01 returns the literal `"off"` string, NOT None, so the explicit-disable provenance survives onto the envelope; a malformed value already degraded to `"medium"` inside config.py); `$CONFIG_CODEX` ← `values.codex` (ALWAYS present — config.py always returns it after `flag > config > default` precedence + `_validate_codex`: `off`/`auto`/`on`, defaulting to `"auto"`; orchestrator-only, consumed by `/deep-review`'s Phase-2c dispatch, NEVER entering the score.py envelope); `$CONFIG_WARNINGS` ← `warnings` (a list, EMPTY when the file is absent or fully valid). Because the flag was threaded through `config.py` above, `values.min_confidence` is ALREADY the precedence-resolved, validated result — this parse just reads it, applying NO further override here. **`idiom_floor` is the ONE knob whose zero-config default is an ACTIVE cap (A1):** on a zero-config run there is no `.vibe-check.toml`, so `$CONFIG_IDIOM_FLOOR` is None here (the degrade default below) — the Phase-3 envelope then OMITS the key and score.py's INTERNAL `medium` default caps idioms at `medium` out of the box (idioms never block finalize). Omission is deliberately NOT a disable for this knob — see the Phase-3 `idiom_floor` envelope-key rule. This does NOT move `GOLDEN_DIGEST`: the digest is over `stable_hash`, which the band-label cap never touches (score.py Plan 32-01 kept the scoring math byte-stable).

**DEGRADE-EVEN-IF-THE-HELPER-MISBEHAVES (Finding #2 corollary — distinct from the Phase-3 step-5 fail-closed scorer gate).** The degrade posture must hold even if `config.py` itself fails. The review NEVER aborts on a misbehaving config reader — this is the OPPOSITE of the mandatory-scorer fail-closed gate at Phase 3 step 5 (which HALTS the review).

**Explicit degrade-vs-warn discriminant — `$CONFIG_PY` empty vs non-empty.** BOTH the "no reader resolved" arm (4) and the "reader misbehaved" arm produce an empty `$CONFIG_JSON`, so the deciding factor is whether a reader was actually invoked — i.e. whether `$CONFIG_PY` is empty:

- **`$CONFIG_PY` is EMPTY (arm 4 — no reader resolved).** `$CONFIG_JSON` is empty and NO warning is emitted. This is zero-config silence (CONFIG-01): a missing reader in a dev/partial install is not a user misconfiguration to surface — no reader + no file ⇒ behave exactly as v2.7. Set `$CONFIG_THRESHOLDS`=None, `$CONFIG_DISABLED`=`[]`, `$CONFIG_TOP_MODEL`=None, `$CONFIG_MIN_CONFIDENCE`=None (no filtering — even if `--min-confidence` was passed, it can't be validated without the reader), `$CONFIG_IDIOM_FLOOR`=None (no reader ⇒ no config ⇒ the Phase-3 envelope OMITS `idiom_floor` and score.py's internal `medium` default still caps idioms — the cap stays ACTIVE at `medium`, matching v2.7-plus-A1 default behavior; None here means "omit", which for THIS knob means "default medium cap", NOT "disabled"), `$CONFIG_CODEX`=`"auto"` (NOT None — a broken/absent reader must still run Codex per today's auto logic; `/deep-review`'s Phase-2c off short-circuit never fires on this arm), `$CONFIG_WARNINGS`=`[]`.
- **`$CONFIG_PY` is NON-EMPTY (a reader was found and invoked) AND it produced a NON-ZERO `$CONFIG_EXIT` OR empty/unparseable `$CONFIG_JSON`** (not valid JSON, or missing the `values`/`warnings` shape). This is a genuine reader failure — emit exactly ONE config-health warning: set `$CONFIG_THRESHOLDS`=None, `$CONFIG_DISABLED`=`[]`, `$CONFIG_TOP_MODEL`=None, `$CONFIG_MIN_CONFIDENCE`=None, `$CONFIG_IDIOM_FLOOR`=None (again OMIT-on-None ⇒ score.py's internal `medium` default cap applies; a broken reader must NOT silently disable the idiom cap), `$CONFIG_CODEX`=`"auto"` (again NOT None — a reader failure degrades Codex to auto, never off), and `$CONFIG_WARNINGS`=`["config: reader unavailable — using defaults"]`.

The warning string has NO leading `⚠ ` — it matches `config.py`'s own warning strings (which are bare), because the Phase-4 config-health render block adds the `⚠ ` prefix exactly once. Emitting `"⚠ config: …"` here would double the prefix at render (`⚠ ⚠ config: …`), so keep the string un-prefixed.

**Zero-config back-compat (CONFIG-01 — the load-bearing constraint).** When there is NO `.vibe-check.toml` AND no `--min-confidence` / `--codex` flag, `config.py` returns all defaults with an EMPTY `warnings` list (it is silent on an absent file). So a repo with no config yields `$CONFIG_THRESHOLDS`=None, `$CONFIG_DISABLED`=`[]`, `$CONFIG_TOP_MODEL`=None, `$CONFIG_MIN_CONFIDENCE`=None, `$CONFIG_IDIOM_FLOOR`=None, `$CONFIG_CODEX`=`"auto"` (the built-in default — Codex runs on auto, exactly as v2.7), `$CONFIG_WARNINGS`=`[]` — which drives byte-identical v2.7 behavior downstream: no `thresholds` key in the envelope (built-in banding), no `min_confidence` key in the envelope (no confidence filtering — `$CONFIG_MIN_CONFIDENCE`=None yields no envelope key, so the score.py filter never runs and GOLDEN_DIGEST is unmoved), no dispatch subtraction, Codex on auto (no `/deep-review` off short-circuit, one legible outcome line), and NOTHING rendered on the config-health line. No warning, no banner, no behavior change. **The ONE deliberate exception is `idiom_floor` (A1):** on this same zero-config path, `$CONFIG_IDIOM_FLOOR`=None ⇒ the Phase-3 envelope OMITS the `idiom_floor` key, and score.py's INTERNAL default caps `category=="idiom"` findings at `medium` — so idioms never block finalize even out of the box. This is the one knob whose default is an ACTIVE cap, by design; unlike `thresholds`/`min_confidence` (whose omission means "no effect"), omitting `idiom_floor` means "apply the default `medium` cap". It is still byte-stable in the sense that matters: it does NOT move `GOLDEN_DIGEST` (the digest is over `stable_hash`, which the post-band band-label cap never touches — score.py Plan 32-01 kept the scoring formula frozen), it changes only the `band` LABEL of an idiom finding that would otherwise have exceeded `medium`.
