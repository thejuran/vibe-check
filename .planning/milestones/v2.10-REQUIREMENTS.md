# Requirements: vibe-check — Milestone v2.10 "Opus 5 rebuild + quiet down"

**Defined:** 2026-07-08 · **Re-scoped:** 2026-07-27 (merged with the Opus 5 adaptation plan by
owner decision — restructure-then-tune, so the noise-wave tuning lands on the system that ships)
· **Re-scoped again:** 2026-09-05 (Phase 39 dissolved — COMPAT-02 returned to backlog 999.12,
COMPAT-01 moved to Phase 44; TRUST-01/02 added to Phase 40; DIET-03 verify-only; DIET-04 capped;
model defaults confirmed unchanged — see the ROADMAP re-scope note under the v2.10 header)
**Core Value:** Catch real defects in a developer's changes before they ship — high coverage,
low noise — so a reviewer who can't manually audit code can trust the agent's output as their
safety net.

**Milestone goal:** Adapt vibe-check to the Opus 5 / Claude 5 model generation (measured
baseline, prose diet, trusted helper resolution, corrected cost anchors), then cut the measured false-alarm rate (6/9) while
holding the catch-rate (8/9) on the re-baselined system — proven on a grown pre-registered
ground-truth test set. Noise-wave design spec:
`docs/superpowers/specs/2026-07-08-quiet-down-v2.10-design.md`.

## v2.10 Requirements

### Ground truth set + Claude-5 baseline (SET)

- [x] **SET-01**: The committed B3 set contains 10–12 organic diffs — 4–6 new (≥1–2
  should-catch, the rest should-quiet, weighted toward clean-but-security/networking-sensitive
  changes), each with patch + provenance sidecar + sealed per-diff answer key, under the
  unchanged v2.9 fail-closed sourcing rules (organic-only, no vibe-check-found bugs,
  reversed-fix should-catches, line-survival-proven should-quiets)
- [x] **SET-02**: The v2.10 pass bar and decision rule (FP-rate ≤ half the pre-change baseline
  AND catch-rate no worse; at most one retune on failed diffs only) are pre-registered in the
  sealed manifest BEFORE any prose/scorer/agent change lands
- [x] **SET-03**: Every diff (new AND carried-over) has a ×3 pre-change baseline recorded on
  the unchanged v2.9.0 plugin running on the current Claude 5 harness (owner-driven runs,
  installed-cache parity pre-flight, v2.9 state-isolation gates) — this baseline is
  simultaneously the Opus 5 re-measure that anchors every later comparison

### Claude-5 compatibility (COMPAT) — Phase 39 dissolved 2026-09-05; COMPAT-01 now lands in Phase 44

- [x] **COMPAT-01**: README and config docs are current for the Claude 5 generation — model
  table, tiering rationale, and configuration section reflect what actually runs (Sonnet 5 /
  Opus 5 / Haiku 4.5; Fable 5.1 opt-in); the `opus`/`fable` top-model allowlist is kept and
  documented; the static cost anchors are corrected to the current price list (Sonnet 5
  $2/$10, Opus 5 $5/$25, Fable 5.1 $10/$50 with 0.025× cache reads, Haiku 4.5 $1/$5; ~30%
  more tokens per character on the 4.7+ tokenizer) and presented as estimates, never as
  measurements (Phase 44)
- ~~**COMPAT-02**~~ — WITHDRAWN 2026-09-05, returned to backlog **999.12**: measured per-pass
  cost has no designed mechanism (the orchestrator cannot tokenize; no harness usage signal is
  known to be readable from command prose) and is off the quiet-down path; a feasibility spike
  gates any future promotion

### Prose diet — restructure for Opus 5 (DIET)

- [x] **DIET-01**: `commands/review.md` and `commands/deep-review.md` are restructured for the
  Opus 5 generation — each rule stated once, anti-improvisation scar tissue removed,
  progressive-disclosure layout — with a materially reduced per-invocation context footprint
  (measured token count before/after recorded); the Phase-0.3 budget-gate price anchors and the
  deep-review cost note are corrected to the current lineup as part of the rewrite (figures per
  COMPAT-01), still rendered as D-01 wide brackets
- [x] **DIET-02**: The remaining high-leverage deterministic prose blocks are extracted to
  tested stdlib-Python scripts per `docs/design/prose-to-code-inventory.md` (the inventory's
  extract-vs-keep judgments honored — extract the ranked families, deliberately keep the rest)
- [x] **DIET-03**: The Phase 4.5→5 state single-writer property is verified on the
  restructured flow — VERIFY-ONLY (2026-09-05): if the restructure dissolves the fix-loop
  desync class for free, record it; if not, return the item to backlog 999.8 rather than
  building state-machine work inside this phase
- [x] **DIET-04**: Each restructure batch is validated before the next lands: behavior
  contract preserved (phases, output paths, fail-closed guards; suite green + envelope
  byte-stability) and a CAPPED live spot-check — 2 diffs (one should-catch, one should-quiet)
  ×1 per batch; the full ×3 B3 spot-check against the SET-03 baseline runs ONCE at phase end
  (catch-rate no worse) — cap set 2026-09-05 to protect the owner-run budget

### Trusted helper resolution (TRUST) — added 2026-09-05, Phase 40

- [x] **TRUST-01**: Every executable helper the commands/agents invoke (`scripts/score.py`,
  `scripts/guard.py`, `scripts/config.py`, and the fix agent's own guard resolution) resolves
  from the TRUSTED plugin install (`${CLAUDE_PLUGIN_ROOT}`, with one explicit owner-set dev
  override env var) — never repo-first; the working-tree arm is removed from every copy, so a
  reviewed repo that plants `plugins/vibe-check/scripts/*.py` is provably never executed and
  cannot replace the containment guard (in-threat-model: the diff is attacker-authored; today
  Phase 3 would run the planted script with no prompt)
- [x] **TRUST-02**: The fix agent validates every path in a finding's file set (regex +
  guard.py containment) BEFORE its first Read/Edit, not only before commit — a traversal path
  is refused before anything touches disk

### Wave 1 — scorer-side (SCORER; the formula freeze lifts, Wave-1-scoped)

- [x] **SCORER-01**: An offline replay harness re-scores archived + baseline run data under
  candidate scorer changes, enforcing the zero-catch-regression guardrail (any candidate that
  would silence a baseline catch is rejected before costing an owner run) — replay data from
  post-diet runs, so tuning targets the system that ships
- [x] **SCORER-02**: B-SEV — banding is less sensitive to the agent's self-declared severity
  label; a borderline finding needs corroborating signal to cross into critical/warning
  (regression-locked)
- [x] **SCORER-03**: B-REWEIGHT — per-agent confidence calibration derived from the
  accumulated ground-truth run data; habitual overconfidence no longer translates 1:1 into
  banding (regression-locked)
- [x] **SCORER-04**: H-LANE — same-site cross-lane findings collapse to one attributed
  finding, and same-model lane agreement stops counting as independent corroboration
  (regression-locked; CATEGORY_DOMAIN twin remapping folds in only if it falls out naturally)
- [x] **SCORER-05**: A live spot-check (the 2 known-noisy should-quiet diffs ×3) confirms
  Wave 1 behaves as the replay predicted before Wave 2 starts

### Wave 2 — agent-side (AGENT; prompt-only)

- [x] **AGENT-01**: The loud lanes (bugs, security, impact + the codex translation contract)
  apply safe-change recognition: a diff that tightens a control (narrows an allowlist, adds
  validation, adds a clamp) is presumptively safe on that axis unless a concrete bypass is
  named
- [x] **AGENT-02**: The same lanes carry confidence ceilings for "sensitive area, no
  demonstrated defect" findings, with the actual B3 false alarms baked in as never-flag
  exemplar classes

### Prove (PROVE)

- [x] **PROVE-01**: The full grown set is re-run ×3 post-change (diet + both waves) and scored
  from state against the sealed keys (complete denominators, no holes, v2.9 isolation gates)
- [x] **PROVE-02**: `RESULTS-v2.10.md` evaluates the pre-registered bar honestly (pass or
  miss) with the honest-limitations section (incl. the tune-vs-measure overlap caveat; the
  baseline and post-change runs are both on the Claude 5 harness, so the comparison is clean
  across the model-generation shift)
- [x] **PROVE-03**: At most one retune is used (failed diffs only, ×3), and its use/non-use is
  recorded

### Close (CLOSE)

- [x] **CLOSE-01**: Shipped as plugin 2.10.0 — annotated tag `v2.10`, README efficacy numbers
  replaced with the v2.10 measurements + caveats (cost anchors static + corrected per COMPAT-01,
  no measured-cost claim), atomic hash-verified publish
