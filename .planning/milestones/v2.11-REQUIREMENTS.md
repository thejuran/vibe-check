# Requirements: vibe-check — v2.11 Quiet loop

**Defined:** 2026-10-01
**Core Value:** Catch real defects in a developer's changes before they ship — with high coverage and low noise — so a reviewer who can't manually audit the code can trust the agent's output as their safety net.
**Design:** `docs/superpowers/specs/2026-10-01-quiet-loop-v2.11-design.md`

## v2.11 Requirements

### Lane gating (GATE)

- [x] **GATE-01**: On a repo where Phase 1d coverage discovery finds no coverage artifact, deep review does not dispatch `test-sufficiency`, and the dispatch announce line states why in one line (dispatch count exactly one fewer there; unchanged everywhere else)
- [x] **GATE-02**: `framework-skill` is dispatched only when triage's `frameworks` includes `skill`; a test pins this and every other lane's selection is unchanged

### Carry-forward integrity (CARRY)

- [x] **CARRY-01**: The review state file has a single writer per field family across Phase 4.5→5 (999.8), pinned by state-shape tests
- [x] **CARRY-02**: An unresolved finding never expires automatically — it persists in carry-forward and the finalize gate until verified resolved against HEAD or closed by an explicit owner decision (dismiss / defer, with reason, recorded like `medium_acknowledgments`)
- [x] **CARRY-03**: Each finding records a decision snapshot (site, evidence, status at the last decision request) so "unchanged since pass N, decision pending" is computable

### Pause batching (BATCH)

- [x] **BATCH-01**: Each fix-loop pass asks the owner ONE card — apply all and rerun / apply selected… / skip and rerun / close out / abandon; the per-finding multi-select appears only behind "apply selected"
- [x] **BATCH-02**: Finalize asks ONE multi-select card for all unacknowledged mediums (dismiss / will-fix per finding) with a single free-text reason for the dismissed set
- [x] **BATCH-03**: Findings unchanged since their last decision request are listed as "unchanged since pass N, decision pending" inside the batch card and never asked about separately
- [x] **BATCH-04**: Behavior under `$TURINGMIND_NONINTERACTIVE` is unchanged

### Fix agent + git safety (FIX)

- [x] **FIX-01**: The fix agent verifies the finding's cited condition no longer holds before committing; an unverified edit is not committed and is reported as unverified (999.15)
- [x] **FIX-02**: Each applied fix lands as its own commit containing only that fix's hunks (999.15)
- [x] **FIX-03**: Detection agents cannot run a mutating git command in the reviewed repo; mutation is confined to the fix agent's trusted commit path, proven by a test (999.20)
- [x] **FIX-04**: `agents/fix.md`'s description matches its actual `opus` pin (W2)

### Measure + release (REL)

- [x] **REL-01**: A full B3 ×3 run on the release candidate shows catch-rate unchanged from Phase 43 (15/15) and false-alarm rate no worse (≤3/18)
- [x] **REL-02**: Owner decision cards per deep-review firing are counted from session transcripts or the orchestrator gate log against the 5.5 baseline; if neither source exists the metric is reported unavailable, never inferred from pass counts
- [x] **REL-03**: The README discloses the `214c7df` post-measurement Codex-wait change (W1)
- [x] **REL-04**: Plugin 2.11.0 is released after release gates (test / security / deep-review) pass on the release commits, before the publish plan
- [x] **REL-05**: Plugin 2.11.1 ships the BATCH-01 Close-out/`--finalize` fix through the same release gates, disclosing the 2.11.0 defect
