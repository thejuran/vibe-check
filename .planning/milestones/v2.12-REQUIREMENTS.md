# Requirements: vibe-check v2.12 Quiet without hiding

**Defined:** 2026-10-08
**Core Value:** Catch real defects in a developer's changes before they ship — high coverage, low noise — so a reviewer who can't manually audit code can trust the agent's output as their safety net.
**Design spec:** `docs/superpowers/specs/2026-10-08-quiet-without-hiding-v2.12-design.md` (local, gitignored)

## v2.12 Requirements

### Holdout (HOLD)

- [x] **HOLD-01**: Six real holdout cases exist, one per type: C1 (newly reachable flaw in an unchanged helper), C2 (protection removed with no equivalent replacement), C3 (an unrelated ordinary bug), Q1 (equivalent protection moved elsewhere), Q2 (unchanged helper weakness with no new exposure), Q3 (valid tightening of input validation).
- [x] **HOLD-02**: Each catch case has a sealed answer key (defect, location, causal failure), and each quiet case has a sealed expected-quiet rationale.
- [x] **HOLD-03**: Cases and keys live outside the repo. Only their content hashes are committed, and that happens before any false-alarm tuning work starts.
- [x] **HOLD-04**: Holdout access is split by role. Tuning work has no access. The evaluation runner can read cases, and scoring can read keys. A PreToolUse hook denies the holdout path during tuning phases, and the results describe this as a barrier, not proof.

### Hardening (HARD)

- [x] **HARD-01**: A git older than 2.36 is detected once at fix-pass start and reported plainly, not first discovered at commit time.
- [x] **HARD-02**: A `git fetch --tags` during a pass no longer halts the pass, under an explicit tag allowance.
- [x] **HARD-03**: The bare-repo `git -C <bare> remote show` / upload-pack probe path flagged in Phase 48 is closed.
- [x] **HARD-04**: WebFetch/MCP guard coverage is either implemented or recorded as an explicit, documented boundary decision.
- [x] **HARD-05**: The fixstage/fixcommit exit table has a single source, and every other copy is generated from it or locked against it by a test.
- [x] **HARD-06**: The standalone fixcommit CLI is retired, and fixstage owns the commit path.
- [x] **HARD-07**: Review agents can run read-only `cd`, `grep` and `sed -n` without a Blocked notice. Mutating git commands stay blocked, as mutation tests prove. Expected vs surfaced Blocked notices are tuned.
- [x] **HARD-08**: The spine finalize trigger matches `--finalize` as a whole token, so `foo--finalize` and `--finalize=1` no longer misroute.
- [x] **HARD-09**: The first-run migration card no longer shows when `.turingmind/` already exists.

### Accepted-fix workflow (FLOW)

- [x] **FLOW-01**: An accepted-fix harness runs accept → apply → rerun → Close out → finalize on disposable copies, in both default-diff and GSD modes, never touching B3 or holdout inputs.
- [x] **FLOW-02**: A harness run counts as complete only when all three conditions hold. (1) The accepted defect is verified fixed and the relevant tests pass. (2) Commits contain only the accepted repair, and unrelated staged and unstaged work is intact. (3) Rerun → Close out → finalize succeeds without manual repair, without silently dropping unresolved findings and without a false success report.
- [x] **FLOW-03**: Preservation runs start from a seeded accepted finding taken from the validated answer-key record, not from detection output. They plant staged and unstaged sentinels, including one in the fixed file outside the fix hunk, and check them byte-for-byte afterwards.
- [x] **FLOW-04**: Two sentinel-free clean-tree runs, one default-diff and one GSD, assert the tree is clean after the fixes are committed and before Close out.
- [x] **FLOW-05**: Every harness run records the owner-decision count and elapsed time, split into waiting on the owner vs execution.

### False-alarm reduction (QUIET)

- [x] **QUIET-01**: For a flaw in unchanged code that the change touches or calls, the reviewer reaches one of three outcomes. Demonstrated new exposure gives a finding. Demonstrated unchanged exposure is capped as pre-existing. Insufficient evidence gives an explicit unresolved assessment. Rule 2's blanket cap is removed.
- [x] **QUIET-02**: A declared value whose consumer is not in the diff is suppressed only on requirement-based evidence that the change's supported behavior does not need it. A comment or plan promising future wiring is not that evidence. It becomes a finding when evidence shows it is required and unwired, and Needs verification when neither can be established.
- [x] **QUIET-03**: A stricter validator that rejects a legacy value is suppressed only on evidence that the value is outside any supported contract (documented config, a public API, persisted data). It becomes a finding when the value is inside one, and Needs verification when the contract cannot be established.
- [x] **QUIET-04**: When a lane judges a replacement as covering a removed protection but misses a bypass path, that judgment and its evidence are surfaced, not left as a filtered capped note.
- [x] **QUIET-05**: The H-LANE site representation under per-member caps (row lead, band, identity, per-member second-opinion semantics) is decided and implemented. The default config stays byte-identical unless the owner accepts a change on the record.
- [x] **QUIET-06**: Unresolved assessments render in a **Needs verification** report group that is never filtered and that folds into the existing batch decision card. Each item persists until it is verified, dismissed or deferred with a recorded reason.
- [x] **QUIET-07**: Needs-verification admission is mechanical and fixed before measurement. An item needs a location (file and line, or a symbol) and a concrete failure. Every rendered item counts as actionable, and the count of items dropped at render time is published.
- [x] **QUIET-08**: Suppression and reachability rule wording stays generic, with no B3 or holdout identifiers. The leakage scanner and mutation-tested prose locks in `scripts/test_agent_prompts.py` enforce this.
- [x] **QUIET-09**: Before the freeze, scorer changes pass the archived replay guard (no protected catch lost), and prompt changes pass live development runs on non-holdout cases. Those runs include new reachability regression cases covering both the demonstrated-new-exposure and demonstrated-unchanged shapes.

### Freeze + gates (FRZ)

- [ ] **FRZ-01**: The release gates (test, security, deep-review) and the milestone integration audit pass on the release candidate before any measurement window opens.
- [ ] **FRZ-02**: A committed freeze manifest records the candidate commit SHA, a content hash of every loaded plugin file, the model configuration (agent pins, `<TOP>`, Codex model and effort) and the harness version.
- [ ] **FRZ-03**: Before every measurement window, the installed plugin files, model configuration and harness version are checked against the manifest. Any mismatch stops the window, and a version string alone is never accepted.
- [ ] **FRZ-04**: Any change after the freeze reruns the affected engineering checks and issues a new manifest. Prompt, scorer, routing or guard changes rerun all detection gates. Fix-path changes rerun the workflow gate. Holdout cases that guided a repair become regression cases, and fresh replacements are sealed for them.

### Measure + release (MEAS)

- [ ] **MEAS-01**: B3 ×3 (36 runs) on the frozen candidate shows false alarms ≤ 3/18 and catches 15/15. Catch credit requires the keyed defect, its location and the causal failure. Any actionable Needs-verification item makes a should-quiet run count as fired.
- [ ] **MEAS-02**: Holdout ×3 (18 runs) on the frozen candidate shows each catch case caught in ≥ 2/3 runs and each quiet case firing in ≤ 1/3 runs. It is judged and reported per case, never aggregated, and labeled a release smoke-test bar.
- [ ] **MEAS-03**: All 16 preservation runs and both clean-tree runs complete under FLOW-02.
- [ ] **MEAS-04**: `RESULTS-v2.12.md` reports B3 per diff, the holdout per case, Needs-verification counts and the accepted-fix baseline (decisions, waiting vs execution time), with an honest-limitations section.
- [ ] **MEAS-05**: The milestone outcome is recorded as MET only when every gate passes with independent holdout evidence. Otherwise it is UNMET. A waiver never converts UNMET to MET. The pre-registered miss policy (one retune, "tuned on the same set" label, fresh holdout cases) is followed.
- [ ] **MEAS-06**: Plugin 2.12.0 is published (main, tag, branch) after the gates. If the outcome is UNMET, it ships only under an explicit owner waiver that names each unmet gate and is disclosed in the README, the tag body and RESULTS.
