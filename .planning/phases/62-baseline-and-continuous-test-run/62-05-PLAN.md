Planner rulings (technical, with rationale):

- Standing check versus capture-time check. The committed footprint record stores each file's path and bytes. The test that runs everywhere (including CI) recounts those bytes straight from `git show BASELINE_COMMIT:<path>` and compares, so it stays valid when a later phase edits `footprint.py`. Agreement with `footprint.path_stats(rev=BASELINE_COMMIT)` is enforced once, at capture: the tool refuses to write a record that disagrees with it.
- Traces cannot be re-extracted on CI because the session files are private and local. So: the record binds each source session by the sha256 of its file (the house rule for gitignored transcripts); the suite tests check the record's structure, labels and git-derivable bytes everywhere; re-extraction from the real sessions is the `verify-traces` command, run on the owner's Mac at capture time and at release gates. Where the session files are absent that command exits 2 with `SESSION FILES NOT ON THIS MACHINE — RE-EXTRACTION NOT RUN`. There is no skipped test.

House conventions (62-PATTERNS.md): stdlib only; plugin modules imported by inserting `plugins/vibe-check/scripts` into `sys.path` if absent; `TestImportSet`; `subprocess.run` with `timeout`; exit codes 0 ok / 1 difference / 2 unusable input; mutants assert the mutation happened; synthetic session fixtures only, never a real log in the repo.
