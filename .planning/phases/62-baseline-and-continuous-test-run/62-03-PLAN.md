The counting rule (planner's definition, D-05). All counts are taken inside fences that open with a line equal to three backticks followed by `bash`, in the Finalize path files, read at a revision:

- `bash_fences`: number of such fences. Each is one command the model runs.
- `write_tool_writes`: number of occurrences, anywhere in the file, of a phrase in `WRITE_PHRASES`. Each is one file the model writes with the Write tool. The phrase list is fixed in the script and justified line by line in CRITERION.md.
- `carried_paste_sites`: for each name NAME that some bash fence prints with a line of the form `printf 'NAME=%s\n' "$..."` (NAME matching `[A-Z_]+FILE`), the number of occurrences of `"$NAME"` or `"$NAME.` in bash fences other than the fence that prints NAME. Each is one value the model copies from earlier output into a later command.
- `printed_literals_distinct`: number of distinct printed names. Reported, but not added to the total, because every copy of a printed value is already counted as a paste site.
- `model_run_steps` = `bash_fences` + `write_tool_writes` + `carried_paste_sites`. This single number is measure (b) of D-01.

The count is static over the declared path, so like the byte figure it is an upper bound: a given Finalize run does not execute every fence.

Warning about 62-RESEARCH.md §"Pattern 4": its table is a prototype and over-counts fences (it lists 18 for `90-finalize.md`; the file has 9 lines that open a bash fence at 2.14.1). Do not copy its numbers. The official figures are whatever this script prints at `BASELINE_COMMIT`, cross-checked by the independent recount in the test.

Situation ids for the comparison workload, shared with plan 62-04 (use these exact strings): `clean-close`, `card-first`, `one-rebuild`, `refused-close`, `fresh-shell-restart`.
