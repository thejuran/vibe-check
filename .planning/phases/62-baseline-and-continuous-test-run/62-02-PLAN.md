## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fork pull request → CI runner | Untrusted code runs on the runner with the job's token |
| GitHub event data → shell | Branch names and PR titles are attacker-controlled strings |
| Third-party actions and pip → runner | Code fetched at run time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-62-07 | Information disclosure | job token on fork PRs | mitigate | `pull_request` trigger only (never `pull_request_target`), `permissions: contents: read`, `persist-credentials: false`, no secrets; locked by `pr_trigger_holds`, `permissions_hold`, `checkout_holds`, `no_secrets_holds` |
| T-62-08 | Elevation of privilege | script injection through event fields in `run:` | mitigate | No `${{ github.event` anywhere in the file; locked with a mutant |
| T-62-09 | Tampering | moved or compromised action tag | mitigate | Both actions pinned to full 40-hex commit ids; `actions_pinned_hold` rejects tags |
| T-62-SC | Tampering | pip install on the runner | mitigate | `pytest==9.0.3` pinned (audited `[OK]` in 62-RESEARCH.md §Package Legitimacy Audit; test runner only, never shipped); `zsh` from the Ubuntu archive; shipped code stays stdlib-only, enforced by the stdlib step |
| T-62-10 | Tampering | a red suite hidden by the log pipe or a soft-fail flag | mitigate | `PIPESTATUS[0]` test after `tee`; no `continue-on-error`, no `\|\| true`; locked by `suite_command_holds` and `runner_holds` |
