<objective>
Close the HARD-03 bare-repo probe path in `gitguard.py` with a dir-target rule that cannot be fooled by the logical-vs-physical cd disagreement, prove every execution vector live-then-refused (including the symlink/`..` vector), and record the HARD-04 WebFetch/MCP boundary as a locked documented decision.

Purpose: a reviewed repo can track an embedded `x.git/` whose config names programs (`remote.origin.uploadpack`, `diff.external`, textconv). Today `git -C <bare> remote show origin` runs them, and a `cd` into the bare dir makes plain `git show` run them too. The original fix compared `realpath` of the cd target with the root — but bash's default cd is LOGICAL: with `R/vendor/x.git/link -> R`, `realpath(R/vendor/x.git/link/..) == R` while `cd vendor/x.git/link/..` lands in `R/vendor/x.git`. So the check must be lexical and conservative: the hook's `_find_repo_root` already returns a physical (realpath) root; a target is the root only if it is `.` or an absolute, `..`-free path whose `os.path.normpath` equals that string. Anything else (relative paths — the hook cannot see the Bash tool's persistent shell cwd —, `..`, symlinked components, subdirectories) is refused for git with a fixed reason. This plan lands BEFORE HARD-07 (plan 52-08) allowlists `cd`, and exports the one resolver 52-08 must reuse, so the cd→git discovery hole (Pitfall 2) is closed before `cd` becomes allowed.

Output: hardened `gitguard.py`, extended `test_gitguard.py` (corpus, live vectors incl. symlink, three mutants, boundary lock), boundary sentence in three documentation sites.
</objective>
