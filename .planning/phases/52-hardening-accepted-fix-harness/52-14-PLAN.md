<objective>
Build the containment policy module the SDK driver (52-10) applies to every session: workspace placement outside the checkout, a plugin snapshot, the session settings JSON (OS sandbox + permission deny rules, fail-closed), the path backstop for file tools, the launch preflight, and the pure evaluator for the live sandbox probe. Stdlib only; no SDK import.

Purpose: the harness grants the session every non-question tool, and a disposable cwd alone restricts nothing — absolute-path reads of the answer keys or writes to the source checkout would be allowed, violating D-14 and the containment boundary, and no after-the-fact scan can detect a read. Claude Code offers an OS-enforced Bash sandbox (Seatbelt on macOS) configured through settings, plus `Read`/`Edit` deny rules for the in-process file tools; this module expresses the policy once, with tests and mutants, so 52-10 only wires it.

Output: `harness_sandbox.py` + `test_harness_sandbox.py`.

- `ClaudeAgentOptions.settings` accepts an inline JSON string; it is merged into the "flag settings" layer (same as `claude --settings`), which has the highest user-controlled priority and is NOT a filesystem source, so `setting_sources=[]` leaves it in force. `ClaudeAgentOptions.sandbox` (TypedDict: enabled, autoAllowBashIfSandboxed, excludedCommands, allowUnsandboxedCommands, network, ignoreViolations, enableWeakerNestedSandbox) is merged into the same JSON; because `failIfUnavailable` and `filesystem` are not in the TypedDict, pass the whole `sandbox` object inside `settings` instead and leave `options.sandbox` unset.
- `sandbox` keys: `enabled`, `failIfUnavailable` (exit at startup when the sandbox cannot start), `allowUnsandboxedCommands` (false ignores `dangerouslyDisableSandbox` retries), `autoAllowBashIfSandboxed`, `excludedCommands`, `filesystem.{allowWrite, denyWrite, allowRead, denyRead}` (paths: absolute or `~/`; narrower rule wins), `network.{allowedDomains, strictAllowlist, …}`. Sandboxed Bash may write the cwd, the per-user temp dir and `additionalDirectories` only; Claude Code's own config paths are write-protected inside those.
- The sandbox wraps shell commands only. Read/Edit/Write/Grep/Glob follow permission rules: `Read(//abs/path/**)` denies reads (and Edit/Write on the same path), `Edit(//abs/path/**)` denies all built-in editing tools except NotebookEdit (add a tool-level `NotebookEdit` deny). Deny rules match when EITHER the requested path or its symlink target matches. `//` = absolute, `~/` = home. A `//`-anchored deny cannot be carved open with `!` patterns.
- Read-only file tools do not prompt inside the working directory and additional directories; outside them they prompt → `can_use_tool` → our backstop denies. Deny rules are evaluated before any callback.
- Model API calls are made by the Claude Code process (outside the sandbox); the harness does not alter `ANTHROPIC_*`/keychain access.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model session → host filesystem | every tool call the session makes must stay inside the disposable copy (write) or the plugin snapshot (read) |
| harness answer keys / source checkout → session | D-14: keys never reach the fix agent; a read cannot be detected afterwards, so it must be prevented |
| sandbox availability → run start | a run without the sandbox would silently downgrade the guarantee |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-52-42 | Information disclosure | Bash `cat <keys>` / `cat <checkout>/…` by absolute path | mitigate | Seatbelt `filesystem.denyRead` on checkout, keys, out dir, credentials; live probe (52-10) |
| T-52-43 | Information disclosure | Read/Grep/Glob tool on a key path (file tools are outside the OS sandbox) | mitigate | `Read(//…/**)` deny rules (match symlink source and target) + `path_allowed` backstop; probe step 5 |
| T-52-44 | Tampering | Bash/Edit/Write into the source checkout or plugin snapshot | mitigate | checkout denied for reads (implies writes); snapshot `denyWrite` + `Edit(//…)` deny + `NotebookEdit` deny; backstop; probe steps 3, 6, 7 |
| T-52-45 | Elevation | `dangerouslyDisableSandbox` retry after a blocked command | mitigate | `allowUnsandboxedCommands: false`; lock m2 |
| T-52-46 | Denial of guarantee | sandbox silently unavailable → unsandboxed session | mitigate | `failIfUnavailable: true`; preflight requires Seatbelt + current probe record; locks m1, m5 |
| T-52-47 | Tampering | symlink planted inside the copy pointing at a protected path | mitigate | backstop resolves realpath AND lexical path; deny rules match either side; mutant m4 |
| T-52-48 | Information disclosure | copy placed under the checkout, denied region carved open | mitigate | `make_workspace`/`build_session_settings` raise when copy or snapshot is under the checkout; `validate_record` (52-13) rejects such a record |
| T-52-SC | Tampering | npm/pip/cargo installs | accept | none in this plan |
