<interfaces>
The repro standard (D-17), applied identically to every flagged pair `(file, NAME)`:

1. **Fresh run.** Take the real setter fence and each real reader fence from the file (found by a needle, never copied into the test). Run each as its own `bash -s` process with an environment of only `PATH`, `VC_ROOT`, `TMPDIR` and the documented bootstrap names the fences need (`GUARD_PY`, `CONFIG_PY`), in a temp working directory prepared as the instruction expects (a `gitfixture` repo where git is used). Substitute the literals the instruction tells the model to substitute (for example the `FINALIZE_MODE` literal, `$ARGUMENTS`). Do not supply NAME.
2. **Control run.** The same fences, same environment, concatenated into one `bash -s` process.
3. **Outcome class**, from exit codes, output and files on disk: `stop` (the fresh run exits non-zero or prints the instruction's halt message where the control does not), `wrong-file` (the fresh run reads, writes or moves a path that differs from the control's), `ignored-setting` (both exit 0 but the fresh run's result shows the setting had no effect while the control's shows it did), `harmless` (same exit code, same output, same files as the control).
4. **Reproduced** means any class other than `harmless`.

Proposed disposition rule (the owner confirms it in plan 63-09; nothing is changed here): `stop` and `wrong-file` → fix (a broken required workflow or a wrong file, as 999.25 was classed); `ignored-setting` → owner decides; `harmless` → pin.

Row shape (after `REPRO_60` in `test_decision_continuity.py`):

```python
     "owner_sees": "<one plain sentence>",
     "proposed": "fix" | "pin" | "owner decides",
     "fixture": "TestRepro63.test_x1_phase_dir"},
]
```
