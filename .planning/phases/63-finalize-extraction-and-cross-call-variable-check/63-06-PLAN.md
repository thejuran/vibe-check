What the helper writes to stderr (from 63-02, D-18): on a counting-stage refusal (state file present but unreadable or malformed; fingerprint file missing, not a regular file or not empty) exactly the one line `carry_state.py finalize-counts` prints at 2.14.1 for that input, taken from `carry_state`'s own constants (for a bad fingerprint file: `carry_state.REASON_HEAD_BLOBS`). 1. The 2.14.1 mint block kept byte for byte: `if BLOBFILE=$(mktemp "${TMPDIR:-/tmp}/vc.XXXXXX"); then` / `printf 'BLOBFILE=%s\n' "$BLOBFILE"` / `else` / the `Finalize stopped — …` echo / `exit 1` / `fi`.

3. `case $? in`: `0)` prints `$FINALIZE_JSON`; `4)` echoes the `finalize_gate.py failed` sentence to stderr and `exit 1`; `5)` echoes the `batch_card.py decisions-report failed` sentence to stderr and `exit 5`; `*)` echoes the `carry_state.py failed` sentence to stderr and `exit 1`.
