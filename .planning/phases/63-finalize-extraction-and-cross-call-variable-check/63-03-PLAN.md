  <behavior>
    On small inline Markdown documents:
    - A fence that sets `X=…` and a later fence that reads `"$X"` is one violation `("X", 0, 1)`
    - The same with `printf 'X=%s\n' "$X"` in the setter fence is no violation; so is `echo "X=$X"`; so is a multi-name format `printf 'A=%s\nX=%s\n' "$A" "$X"`
    - A reader fence that assigns `X` on an earlier line than its read is no violation; a read on a line before the re-assignment is a violation
    - `'$X'` inside single quotes, `\$X`, a `$X` in a comment line, and a `$X` inside a heredoc with a quoted delimiter are not reads
    - `${X}`, `${X:-d}` and `"$X"` are reads; `$1`, `$?`, `$@`, `$$`, `$#` are never reads
    - Assignment forms recognised: `X=`, `X+=`, `if X=$(`, `export X=`, `local X=`, `readonly X=`, `declare X=`, `for X in`, `read X`, `read -r X Y`
    - A name read but set in no earlier fence of the same document (a cross-file name such as `VC_ROOT`) is no violation
    - An indented fence and a four-backtick fence are both scanned; a fenced block in another language between them is skipped, including a `$X` inside it
    - Text outside fences never counts as a set or a read
  </behavior>
  <action>
